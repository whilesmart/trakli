# Trakli — FlatRun template

A one-click FlatRun template for the full self-hosted Trakli stack
(API + worker + web UI, with MySQL and Redis). It is adapted from
[`docker-compose.selfhost.yml`](../docker-compose.selfhost.yml) (issue #308, PR 1).

## What's in this folder

| File | Purpose |
| --- | --- |
| `docker-compose.yml` | The stack, in FlatRun's format (`${NAME}`, external `proxy` network, `expose:` instead of `ports:`) |
| `metadata.yml` | Template metadata: name, description, quick actions, generated `.env`, and backup config |
| `README.md` | This file |

The template pulls the published images `ghcr.io/trakli/webservice` and
`ghcr.io/trakli/webui` — no source build is required.

## Deploying

1. Deploy the **Trakli** template from the FlatRun marketplace.
2. FlatRun generates `.env` from `metadata.yml` and prompts for the variables
   listed below.
3. **Generate the app key** — open the deployment's *Quick Actions* and click
   **Generate App Key** (`php artisan key:generate --force`). This writes
   `APP_KEY` into `.env`; you do not generate it yourself.
4. **Run migrations** — click **Run Migrations** (`php artisan migrate --force`).
   FlatRun has no deploy-time hook for one-shot ordering, so this is a manual
   step by design (a platform limitation, not a bug).
5. Open the web UI URL FlatRun assigned, register, and create a transaction.

Optional features are off by default and enabled with Compose `profiles`:

- AI assistant: `smartql` service — enable the `ai` profile and set
  `GEMINI_API_KEY` / `LLM_API_KEY` / `SMARTQL_URL` in `.env`.
- Realtime: `reverb` service — enable the `realtime` profile.

## Variables you must provide

| Variable | Notes |
| --- | --- |
| `APP_URL` | Public URL of the API (the `app` service's FlatRun URL) |
| `CORS_ALLOWED_ORIGINS` | Web UI's public origin — must exactly match the `webui` service's FlatRun URL (protocol + host) or the browser silently rejects API responses |
| `NUXT_PUBLIC_API_BASE_URL` | `APP_URL` + `/api/v1` |
| `DB_DATABASE` / `DB_USERNAME` / `DB_PASSWORD` | MySQL credentials (the `mysql` service is created for you) |
| `DB_ROOT_PASSWORD` | MySQL root password for the container |
| `REDIS_PASSWORD` | Redis password |
| `IMAGE_TAG` / `WEBUI_IMAGE_TAG` | Pinned semver release tags — never `latest` |

## Notes & deviations from the execution plan

- **Migrations are a manual quick action:** per the execution plan (§0.5),
  FlatRun has no one-shot deploy hook, so `migrate` is exposed as the
  **Run Migrations** quick action. After the first deploy, click it once. This
  is a platform limitation, not a bug — do not add a one-shot `migrate`
  service. (The `quick_actions` list also includes **Generate App Key**.)
- **`APP_KEY` generation:** the plan assumed a `secret: base64:` FlatRun
  mechanism. No such field exists in FlatRun's actual templates, so `APP_KEY`
  is generated by the **Generate App Key** quick action instead. Switch to
  native secret generation if FlatRun adds support.
- **Inbound routing:** `app` and `webui` are both attached to the external
  `proxy` network (they each need a public URL — the browser calls the API
  directly). Verify the proxy assigns each its own routable URL on a real
  FlatRun account; `container_port: 3000` targets the web UI.
- **Storage:** the app/worker `storage/` uses a named `app_storage` volume
  (this repo has no `storage/` directory); the volume is seeded from the image
  on first run.

## Gating

- Requires a **FlatRun publisher account** for the `trakli` org (does not exist
  yet) to submit the template to the marketplace.
- Requires the published `ghcr.io/trakli/webservice` and `ghcr.io/trakli/webui`
  images at the pinned tag.
